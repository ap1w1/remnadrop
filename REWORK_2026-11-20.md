# RemnaDrop: 20 ноября 2026 — дополнительные изменения

## Включено

- Пункт «Мониторинг» в меню ведёт на просмотр. Кнопка с шестерёнкой открывает настройки мониторинга; отдельный пункт меню настроек удалён.
- В «Настройки → Стиль оформления» доступны цвет акцента, фон, цвет поверхности. Сохранение локально в браузере (localStorage), **не глобально для всех администраторов**.
- RW Prime и GitHub удалены из верхних управляющих элементов. Кнопка сердца открывает диалог пожертвований с копированием адресов и предупреждением о выборе сети.
- Логотип DPI Checker заменён на `frontend/public/dpi-checker.svg` по приложенному макету. В меню и заголовке используется JSX-компонент с теми же SVG-путями.
- У ноды появилось необязательное поле `backupProxyUrl` (SOCKS5). Запись в базу, контракты и интерфейс включены. Fallback срабатывает только при явных ошибках соединения (`ECONNREFUSED`, `EHOSTUNREACH`, `ENETUNREACH`, `ERR_PROXY_CONNECTION_FAILED`); TLS-ошибки не должны запускать обход. При наличии резервного прокси, но без основного, сначала используется прямое соединение.
- Subpage Builder: в `brandingSettings` добавлены `telegramChannel`, `telegramBot`, `webPage`, `webPageStub` и поддержка шаблонов в `supportUrl`. Плейсхолдеры: `{{EMAIL}}`, `{{ID}}`, `{{USERNAME}}`, `{{TELEGRAM_ID}}`. В публичный endpoint информации о подписке добавлено поле `resolvedLinks` с URL-encoded значениями. Для использования в отдельно развёрнутой subscription-page её frontend должен читать `resolvedLinks` — автоматически эти поля в её шаблоны НЕ встраиваются.

## Ограничения, на которые важно обратить внимание

- Dockerfile.dev изменён для сборки локальных TypeScript-контрактов, поскольку опубликованный `@remnawave/backend-contract` этих полей ещё не содержит.
- Потребуется миграция `backend/prisma/migrations/20261120220000_node_backup_proxy/migration.sql`. Без неё backend НЕ запустится корректно.
- Изменения не тестировались с реальной PostgreSQL, реальной нодой и полным Docker build. Статический парсер TypeScript/TSX проходит. **Не переключайте production-контейнер до успешной сборки, тестирования и создания проверяемой резервной копии БД**.
- Ошибка `self-signed certificate in certificate chain` не является поводом отключать `rejectUnauthorized`. Проверить `SECRET_KEY`, CA панели и ноды, порт подключения, TLS-прокси, который может подменять цепочку. Не пересоздавайте ключи до диагностики.

## Разработка и проверка

```bash
cd /opt/panel-build/remnadrop-updated
docker build --progress=plain -f Dockerfile.dev -t panel-fork:2.8.1-rework-test .
```

Команда **только собирает образ**; не изменяет работающий контейнер. После этого используйте тестовую копию базы и миграцию с проверенным откатом. Не запускать `docker compose up` на рабочем сервере без резервного плана.

## Как прочитать лог TLS ноды

```bash
docker logs --tail=300 remnanode 2>&1 | grep -aiEn 'certificate|tls|self.signed|error|x509' | tail -80
```
