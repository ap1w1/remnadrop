# RemnaDrop 2.8.1 — обновление: DPI, графики, API и установка

## Изменения

1. В DPI Checker кнопка «Перейти в бот» на `https://t.me/dpi_checker_robot?start=p453722`.
2. Списки выбора нод на экранах мониторинга, автоматизаций, выбора хостов, фильтров пользователей и торрент-отчётов показывают флаг и адрес/IP при наличии в API; Spotlight уже показывает IP отдельно. Не все сторонние кастомные селекторы покрыты.
3. В Subpage Editor переменные `{{EMAIL}}`, `{{ID}}`, `{{USERNAME}}`, `{{TELEGRAM_ID}}` убраны в информационное меню (кнопка i), откуда копируются нажатием. `support-url` опционален: если пуст, используется `supportLink` из общих настроек панели при формировании `resolvedLinks` сервером. Самостоятельную страницу подписки требуется обновить для чтения `resolvedLinks`.
4. В настройках мониторинга добавлен срок хранения 1–365 дней. Настройка сохраняется в таблице `monitoring_preferences`; очистка метрик и событий по расписанию. Изменение значения на 1 день действительно удаляет старую историю при следующем сборе.
5. На графике мониторинга появились временные маркеры пороговых срабатываний и изменений подключения (красный круг с ! и зелёная отметка восстановления), пунктирные линии и подсказки. Переходы вычисляются по зафиксированным минутным сэмплам и не могут отображать события, произошедшие до установки мониторинга.
6. Последним пунктом меню открывается «Документация»: 218 API-методов из контрактов/контроллеров и 44 именованных вебхук-события, поиск по категориям, JSON с подсветкой синтаксиса и копирование. Каталог статический и отражает экспортируемые маршруты в архиве, а не автоматически актуализируемую OpenAPI-спецификацию. Коды ответов, детали DTO и схема авторизации различаются по маршруту, поэтому показаны сокращённые примеры.

## Установка одной командой с Windows

Скачайте **remnadrop-ops-installer-bundle.zip**, распакуйте его в любую папку, затем в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\install-remnadrop.ps1 -Server root@IP_ПАНЕЛИ
```

Сценарий сам отправляет ZIP на сервер через SCP, распаковывает исходники, собирает Docker-образ, проверяет присутствие новой страницы/миграции, создаёт независимый дамп PostgreSQL и экспорт контейнера, готовит rollback image, применяет миграции и проверяет healthcheck. Нужны Windows OpenSSH (ssh.exe, scp.exe), root-доступ к VPS и Docker Compose, Python3 и unzip на VPS.

При ошибке программа останавливается, пишет путь резервных копий в `/opt/remnawave/.last-ops-update-backup`. **Система не выполняет автоматический откат мигрированной БД**, поскольку нужно учитывать совместимость схемы. Не запускайте старый образ на новой схеме вручную.

## Серверная установка, если исходники уже загружены

```bash
cd /opt/panel-build/remnadrop-ops-20261120/remnadrop-updated
sudo bash ./upgrade-fork.sh
```

## Обязательная проверка

```bash
export COMPOSE_FILE="$(cat /opt/remnawave/.panel-compose-files)"
docker compose --project-directory /opt/remnawave ps
docker logs --tail=100 remnawave
```

Обновление панели само по себе не решает `self-signed certificate in certificate chain` на ноде. Не отключайте проверку TLS; сверяйте CA панели и сертификат, который нода предъявляет через порт управления.

## Статус проверки

Синтаксические проверки TypeScript/TSX, Bash и ZIP проведены. Полная Docker-сборка и миграция на реальном PostgreSQL в этой среде не проводились. Сначала разворачивайте на тестовом экземпляре.
