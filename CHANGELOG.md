# Изменения RemnaDrop

Этот список описывает возможности форка относительно базовой Remnawave 2.8.1. Точные исходные ревизии backend и frontend записаны в [`upstream.lock.json`](upstream.lock.json).

## Пользователи и квоты

- Несколько групп квот на пользователя. Одна группа может объединять несколько нод с общим лимитом; для отдельной ноды создаётся группа из одной ноды.
- Создание, изменение, сброс и удаление групп через интерфейс и API. При создании группы расход начинается с нуля.
- Предупреждения по нескольким порогам, блокировка исчерпанной группы и события для вебхуков.
- Переменные квот в названиях хостов. При отсутствии подходящей группы переменная квоты заменяется пустой строкой.

## Ноды и инструменты

- История показателей нод, события на графиках, выбор нескольких нод и показателей, экспорт CSV и настройка часового пояса отображения.
- Схема связей «нода → профиль → сквад → inbound → хост» с состоянием нод, выбором пути и масштабированием.
- Правила автоматизации для нескольких нод, предварительный просмотр действий и журнал выполнений.
- Учёт SSL-сертификатов по нодам и напоминания до истечения срока.
- DPI Checker с историей проверок и настройкой прокси для API.
- Встроенный Limiter и управление Cloudflare DNS из панели.

## События и интеграции

- Журнал событий панели: состояние нод, входы администраторов, автоматизации, оплата, сертификаты и пороги нагрузки.
- Уведомления в браузере с выбором типов и исключениями для нод.
- Вебхуки событий форка через штатные настройки Remnawave; примеры квот приведены в [`QUOTAS.md`](QUOTAS.md).
- Дополнительные маршруты и структуры запросов перечислены во встроенной документации API панели.

## Установка и сопровождение

- Команда `remnadrop check` проверяет установленную Remnawave 2.8.1 до обновления.
- `remnadrop update` собирает образ из закреплённой ревизии, создаёт резервные копии, проверяет восстановление БД и состояние панели после перехода.
- При доступном исходном образе обновлятор использует его для отката без повторного экспорта файловой системы контейнера; перед сборкой проверяется запас свободного места.
- CLI учитывает переписанную историю `main`: сохраняет прежнюю ревизию источников и продолжает только для ранее полученного из `origin/main` коммита.
- Команда отката и местоположение резервной копии выводятся установщиком. Подробности в [`INSTALL.md`](INSTALL.md).

Скриншоты интерфейса с синтетическими данными находятся в [`docs/screenshots`](docs/screenshots).
