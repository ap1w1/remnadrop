# RemnaDrop 2.8.1 — проверка исправлений перед выкладкой

**Статус:** исходники обновлены; полный набор проверок на чистой Remnawave 2.8.1 ещё не пройден. Не считать эту редакцию production-ready до окончания испытаний.

## 1. Безопасная проверка исходников

На отдельном тестовом VPS (или на сервере с достаточным объёмом диска, без замены работающего контейнера):

```bash
cd /opt/remnadrop-git
git pull --ff-only origin main
python3 -m unittest discover -s backup-agent -p 'test*.py' -v
set -o pipefail
docker build --progress=plain -f Dockerfile.dev -t panel-fork:2.8.1-qa-20261121 . 2>&1 | tee /root/remnadrop-qa-build.log
```

Сборка образа не запускает миграции на рабочей базе, не заменяет работающий контейнер. При ошибке проверяйте последние 80 строк лога.

## 2. Интеграционные тесты на восстановленной копии PostgreSQL 2.8.1

- Сделать pg_dump производственной БД, проверить pg_restore --list, восстановить **в отдельную изолированную БД**.
- Проверить историю всех upstream Prisma-миграций и затем выполнить только migrate:deploy.
- Проверить запуск API, processor и scheduler, JWT/admin вход, subscriptions, выдачу хостов, сквады и узлы.
- Проверить очистку создания временного пользователя/сквада DPI Checker при успехе, ошибке и отмене. Убедиться, что исходные сквады пользователей не меняются.
- Проверить индивидуальные лимиты для пользователя в нескольких пересекающихся сквадах: превышение ограничивает **только одну ноду**, ручной сброс одной ноды не меняет остальные, удаление лимита разблокирует ноду через синхронизацию, общий сброс не изменяет индивидуальные лимиты.
- В бэкапах создать минимум два успешных архива, запросить удаление первого, проверить работу агента и защиту последнего; удалить назначение и проверить, что физические архивы сохранились.
- Проверить страницу схемы связей для одной, нескольких и всех нод, включая скрытые и хосты без активного inbound.
- Проверить редактор страницы подписки: импорт/экспорт, редактирование каждого раздела, проверка валидации и сохранение в исходной структуре JSON.

## 3. Выкатка на работающую панель

Не использовать непроверенный образ для рабочего переключения. Перед выкладкой зафиксировать Git SHA, сделать свежий дамп PostgreSQL и архив конфигураций, проверить возможность **тестового восстановления**, сохранить старый совместимый Docker-образ и план отката. Старый образ нельзя автоматически запускать на уже мигрированной схеме БД без восстановления согласованного дампа.

## Что изменено в этом раунде

- Топология: выбор одной/нескольких/всех нод, хосты и fallback-связи для неактивных inbound, без отдельных верхних карточек ноды и профиля.
- DPI Checker: временный изолированный внутренний сквад по нужным inbound, очистка после запуска, одна кнопка запуска проверки вместо расчёта с отдельным подтверждением стоимости.
- Лимиты: сброс и удаление лимита конкретной ноды; общий цикл сброса подписки сохраняется.
- Бэкапы: правый справочник Remnawave, компактные плитки, отдельное удаление назначения и архивов, защита последней успешной копии.
- Редактор страницы подписки: удалены жёсткие оформления части полей и карточек, возвращена цветовая схема Mantine. Дополнительно необходима визуальная и функциональная проверка всех блоков.
